## 2024-06-25 - Command Injection in Git Filter-Branch
**Vulnerability:** A command injection vulnerability was present in `git-engine.service.ts` where user-provided filenames were enclosed in double quotes during the construction of a `git filter-branch` shell command. This allowed potential execution of arbitrary shell commands embedded within filenames (e.g., via `$()` or backticks).
**Learning:** Shell commands generated dynamically and executed via methods like `filter-branch` `--index-filter` or `exec`/`spawn` with shell parsing must treat all dynamic input as potentially hostile. Standard string replacements (like replacing double quotes) are insufficient because the shell still interprets variables and command substitutions within double quotes.
**Prevention:** To prevent command and option injection when dynamically constructing shell commands, always enclose user-provided paths and filenames in single quotes (since the shell does not expand anything within single quotes). Additionally, safely escape any internal single quotes (e.g., using `'\''`), and prefix filenames with `--` to explicitly indicate the end of options and prevent option injection.
