## 2024-05-31 - [Credential Exposure] Fix Hardcoded Credentials in Remote URLs
**Vulnerability:** The application was constructing target URLs for Git operations by embedding the API token directly into the URL (e.g., `https://x-access-token:${token}@github.com/...`). This exposes the sensitive token in system process lists (like `ps aux`) when Git commands are spawned, as well as in potential error logs or debug outputs.
**Learning:** Embedding secrets in URLs passed to shell commands is a major security risk because command-line arguments are globally visible to other users and processes on the system.
**Prevention:** To pass credentials securely to Git operations, use environment variables in combination with Git's `credential.helper` configured inline via `-c` flags. Specifically, setting `credential.helper` to execute an inline shell function that reads the password from an environment variable (e.g., `$GITHUB_TOKEN`) prevents the secret from appearing in the command-line arguments.
