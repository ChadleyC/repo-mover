## 2024-05-03 - Exposing Git Authentication Tokens via Remote URLs
**Vulnerability:** The application was injecting authentication tokens directly into the `targetUrl` constructed for GitHub pushes (`https://x-access-token:<token>@github.com/...`). This can lead to credential exposure in terminal command histories, system process lists (`ps aux`), shell execution traces (`set -x`), and git logging.
**Learning:** Even though `child_process.spawn` attempts to mask the `env`, embedding tokens as command-line arguments (which URLs effectively become when passed to tools like `git lfs push --all <url>`) fundamentally bypasses those protections and remains visible process-wide.
**Prevention:** Avoid embedding sensitive information within remote URLs whenever feasible. Instead, pass credentials implicitly by injecting Git configurations via `credential.helper` logic that echoes tokens directly read from securely managed environment variables. Use `git -c credential.helper=...` and ensure environment variables with secrets are used.
